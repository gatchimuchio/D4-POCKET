## 操作と観測

登録画面では`.env`と`secrets`を秘密pathとして除外し、他Workspaceや資格値は入力しなかった。native Owner確認画面は、Broker process中だけRuntime／Workspaceを登録し、Task用Permission、Approval、Trust、Credentialは生成せず、Taskを実行しない旨を表示した。確認後にBrokerは登録を受理した。

通常D4 Pocket Auditの末尾は次の順だった。

| 識別子 | 操作 | 判定 | 射程 |
|---|---|---|---|
| `broker-audit-8891` | Agent CLI／Workspace登録 | `received` | Owner確認済みの登録要求。Task用Permissionではない |
| `broker-audit-8892` | Runtime資源登録 | `recorded` | 内部状態 |
| `broker-audit-8893` | Workspace登録 | `recorded` | Permission拒否を含む登録状態 |
| `broker-audit-8894` | Agent CLI／Workspace登録 | `accepted` | 起動中登録のみ。Task未実行 |

`broker-audit-8891`と`broker-audit-8894`の証拠源は`LIVE_RUNTIME`。Audit record自体には時刻fieldがないため、ID順は因果順の補助であり精密な時間相関を証明しない。

応答不能のGUI processを停止した後、Launcherは`FRONTEND_EXIT_FAILED`を表示した。続いてLauncherも終了し、Broker終了Audit `broker-audit-8895`が記録された。これは正常終了のPASSではなく、UI停止後の回復・終了観測である。
