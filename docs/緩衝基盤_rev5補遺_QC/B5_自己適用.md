# B5 自己適用記録

状態: OPEN（B5の一局所実証。B5全体のAcceptanceではない）

## 対象

Windows上でD4 PocketのFlutter検証出力がOneDrive同期領域に生成され、深い生成pathが同期不能になる問題に対し、検証だけをOneDrive外の一時source snapshotで実行する経路を追加した。Flutterは引き続きUI／検証対象であり、Authority境界に変更はない。

ユーザー提供画像では、`mobile_flutter/build/flutter_secure_storage/...`配下の長い生成pathをOneDriveが同期できないと表示していた。元の失敗時のsource commitと正確な検証commandは記録されておらず、今回と同一source・同一commandでの失敗再現ではない。

## 実装した介入

- `tooling/flutter_workspace.py`が現在のHEAD、tracked差分、non-ignored untracked sourceを一時snapshotへ再構成する。source commitと差分を含むfingerprintを作成時と終了時に照合する。
- 一時配置先がrepository／OneDrive配下、またはWindows reparse pointである場合は拒否する。特殊file、symlink、root外path、snapshot衝突も拒否する。
- Windowsの`APPDATA`／`TEMP`／`TMP`、Flutterの`PUB_CACHE`、Rustの`CARGO_TARGET_DIR`をsnapshot／一時領域へ向ける。`PUB_CACHE`と`CARGO_HOME`は既定値がsource／OneDrive外なら共有し、今回のWindowsではその条件に合致した。
- `tooling/validate_all.py`はFlutter analyze／testと必要なDesktop Rust helper buildを同じsnapshot内で実行する。helper build失敗時は依存するDesktop Flutter testを実行しない。
- 終了時にsource identityを再確認し、一時領域のcleanup失敗を検証失敗として扱う。

## 証拠の限界

今回の結果は、現行dirty sourceでWindows開発用Flutter検証をOneDrive外のsnapshotから実行でき、検証のための生成物を一時領域から回収できたことを示す。OneDrive設定、同期service、過去に表示されたitemの同期状態は変更・確認していない。

元の警告と今回の成功はsource revision・記録条件が一致せず、OneDrive上での同一command negative controlも行っていない。従って、OneDrive問題の原因を完全に閉じた、同期が再開した、全Flutter／Windows環境が修復された、または`BUF-T04`／`BUF-T22`がPASSしたとは判定しない。`PUB_CACHE`／`CARGO_HOME`はOneDrive外のユーザーcacheを共有し、性能・長期実行・他OS・installed productは今回の検査対象外。
