## 1. 有限な受入条件

B3ではB0の原因対応行を共通機構・既存是正・実験・試験・残余のいずれかへ対応づける。原因行の対応済み数と解決数を混同しない。失敗根因を知らない行は未知のままとし、「吸収不能」へ移さない。

B0の最新cause-map集計は実行記録184件／原因対応153行（2026-10-10、#26931288196／#26932073214／#26935106026のsource-history照合後）。初期直接参照なし56 runのうち37件はcause-map済み、19件は未解明。legacy validationでは17 jobの個別原因証拠が不足している。B3全体のCLOSED条件は153原因対応行すべての分類と、保護境界・残余の明示である。

本記録の最初の局所単位B3-M01は、target／toolchain／API contractの不一致と、該当gateの是正である。これは一般的な環境bufferを導入する条件群ではなく、既存source／SDK／lock／test contractを直して指定targetのgateへ再接続する既存機構として扱う。

## 2. 分類語

| 分類 | 意味 |
|---|---|
| `既存機構成立` | source／contract／harnessの責任面を修正し、該当したgateを通過した。後続の別failureや製品全体成功を含意しない。 |
| `吸収実証` | B1の意味保存条件を保つ非権限介入が、同一対象の元Toolを通して因果効果まで確認された。 |
| `吸収不能を実証` | 対象を制約する直接根拠があり、保護・権限境界を守ると介入できないことを確認した。 |
| `未成立／未知` | 成立を観測していない。ログ欠落・後続別run・未実行を成功や吸収不能へ読み替えない。 |

「既存機構成立」は新しい緩衝の効果を表さない。各行に記録された後続証拠の範囲だけを採る。
