# v3からv4への差分・移行台帳

基準：v4採用前 `main=d503a4ef6daac8942abd1cb011442ce28c78ec55`。
比較対象：採用済み `docs/QE_2026-11-09/` と受領原本 `docs/QE_2026-11-13/`。
目的：現行要求をv4へ切り替え、旧要求・履歴・安全境界を非遡及で保持する。

## 意味上の移行

| 領域 | v3で保持していた意味・状態 | v4の現行条件 | 移行処置 |
|---|---|---|---|
| 製品主語・目的 | 汎用Runtime Operation Shell、AI実仕事、Rust Broker唯一の実権限 | 一般的な標準OSの使用者が通常導入し、AI実Task→Tool/Runtime作用→結果再消費→完了/停止/回復まで利用可能 | 意味を継承し、製品利用体験・導入責任・完了条件を明文化。利用者へSDK/CLI/Source Buildを要求しない |
| 工程 | A〜Jを同じBUILD期間で並行し、W00〜W08は受入座標 | E0設計・全体台帳→E1全体BUILD→E2接続→E3 BUILD_COVERED→E4全体QC→E5標準OS QA→E6 Release Review | W/A〜Jを直列Gateにしない。W02を他線の着工条件にしない。局所PASSを全体完了へ昇格しない |
| OS保証 | Windows優先、Linux native必須。旧版に残る物理端末証拠・凍結条件を保有 | 宣言したOS/version/arch/配布物に対するVM/hosted/Emulator/Simulatorのinstalled製品検証。Windows所有実機確認。他OS物理端末は必須でない | 旧実機条件は履歴に保持し、現在のblocker/validator/説明を標準OS実物検証へ移行。未検証をSUPPORTEDにしない |
| 安全・Authority | Rust Broker、Permission/Approval、秘密、Audit、Recovery、Content Exposure等 | 同じ不変条件を全OS・AI・Tool・Export経路に維持 | 緩和なし。実行環境・Codex開発委任・製品利用者のPermission・Owner GOを分離 |
| 全要求母集団 | N01〜N11、P/C/Phase/K、Buffer、B/Q/FQ、監査、OS別要求 | 同じ母集団を実Producer→Consumer、拒否/回復、証拠へ接続 | 削除・再採番なし。E0 ledgerで旧IDとv4線/consumerを結ぶ |
| Release | 18件、16 unresolved/2 resolved、`release_ready=false` | 18 IDと旧status・歴史を保持し、現候補を個別評価 | 採用で解消しない。モバイル物理端末項目だけ受入媒体を移行し、配布資格・安全・Owner GOは独立維持 |
| Q0〜Q7 | DEFERRED、Final QAは製品全体の後段 | E3後の同一候補でQC/QA。Q7は責任者判断 | v4施工中にQ0〜Q7正式合格を主張しない。重大な安全否定検査はBUILD時にも行う |
| 進捗・証拠 | v3の基準HEAD、実行記録、過去FAIL/CLOSED | v4のHEADと条件へ別記録 | v3記録を編集してv4状態へ書き換えない。証拠はSource/Artifact/OS/条件に結合 |

## 適用の境界

- v3で記録されたstatus、日時、失敗、CLOSED範囲は当時の事実として固定し、v4による再判定・削除をしない。
- 物理端末の非必須化は試験手段の変更であり、Mobileのnative安全境界、製品機能、通常配布、署名/Store資格の免除ではない。
- Linuxは完全対応を要する独立製品対象。WSL/WSLg/headless/cross-compile/fixtureをLinux native installed productの合格にしない。
- 移行漏れの検出は現在の文書・validatorの責任である。過去の時点を記録する履歴文書は「当時」と識別して保持する。
