# Host操作面

## 位置付け

C18のHost操作面は、C17のHost registryをD4 Pocket Desktopへ接続する。`Host一覧`は通常認証済みIPCから取得し、Hostの表示名、Platform、接続状態、Trust、Runtime／Agentのboundedなsummaryだけを表示する。

現行Hostの能力一覧は、起動時またはHost Centerの明示的な再取得操作でBrokerから受理した`ホスト能力`をHost IDで照合し、Host Centerへ投影する。再取得は認証済みIPCの読取要求であり、応答のoperation、accepted状態、`LIVE_RUNTIME`証拠、Audit参照、schemaを検証する。Broker観測Hostと一致しない登録Hostの能力は未観測のままにする。能力の状態・証拠種別・理由は利用可能性の表示であり、Permission、Approval、Authority、Trust、Credentialを生成しない。更新失敗時は最後に受理した値を明示して保持し、更新成功と表示しない。

Host metadataの証拠種別は`INTERNAL_STATE`であり、未接続HostのRuntime／Agent一覧をliveであるかのように生成しない。登録時のRuntime／Agent件数はsummaryであって、個別一覧の観測証拠ではない。

## Host切替

`Host切替`は通常IPCの表示コンテキスト操作であり、Rust BrokerがHost IDをregistryと照合して監査する。切替はPermission、Approval、Authority、Credentialを生成しない。前のHostの承認、Permission、Authorityを新しいHostへ持ち越さず、receiptは`承認状態=not_reused`、`authority_strip=true`、`metadata_only`に固定する。

存在しないHost、未知field、owner control経路からの切替要求は拒否する。Brokerが切替を監査できない場合、UIは切替成功を表示しない。

Desktopは受理済みの表示切替を履歴とWorkspace Inspectorへ通知する。Inspectorは旧登録の選択、取得済み本文・差分、表示範囲の選択を消去し、現在の登録を取得する。旧Brokerまたは旧Host表示の承認応答を理由に、新しいWorkspaceの表示を更新したり操作を再送したりしない。

## Host表示コンテキスト停止

`Host停止`は、Host Centerが現在選択しているD4内の表示コンテキストだけを解除する通常認証済みIPC操作である。Rust Brokerは登録済みHost IDとmetadata-only状態を照合し、受信・受理を永続Auditへ記録する。受理後にDesktopは選択中Hostを解除し、Host切替と同じgeneration通知でWorkspace Inspector、History、Evaluationの旧表示と進行中の旧応答を無効化する。BrokerはHost停止をHost切替と同じsnapshot／AI Edit境界として扱い、停止前のCompose Catalogと適用receiptを再利用させない。現在のBroker能力は選択状態と独立した読取観測として保持する。未登録Host、owner control経路、未知field、Audit失敗では解除成功を表示しない。

この操作はremote接続を切断せず、遠隔HostやRuntimeのprocessを停止しない。receiptは`停止範囲=display_context_only`、`遠隔Host停止=false`、`authority_strip=true`、`権限生成=なし`を固定し、Permission／Approval／Authorityを失効・移転・再利用する新しい規則も生成しない。解除した選択はHost一覧から再選択できる。Hostの実接続・process停止は別の実作用契約が成立するまで未対応として扱う。

## Runtime／Agent一覧

選択Hostを現在のBroker実行Host（local）として扱えるのは、product初期化で受理した`snapshot_source=broker`のホスト能力観測とHost IDが一致する場合だけである。`mock`、fallback、診断、未検証snapshot、表示名、Host metadataだけではlocal／remote区分やlive状態を推定しない。

一致した場合だけ、そのHostのRuntime／Agentを現在のBroker観測として表示する。一致しない登録Hostは別Hostとして表示し、remote接続と個別Runtime／Agent状態は未観測のままにする。registryのRuntime／Agent件数はmetadata summaryとして別表示し、個別live一覧へ展開しない。snapshot sourceがBroker確定経路でない場合は、全HostのRuntime／Agentを未観測として扱う。

Host registryの接続状態・Trustは登録metadataとして表示し、Broker現在HostのLIVE_RUNTIME観測と混同しない。ホスト能力画面の`degraded`は観測された機能状態の投影であり、Permission、Approval、Authority、Credential、接続Trustを生成しない。

## Host metadata登録

DesktopのHost操作面は、Linux／GTKとmacOSで公開metadataの登録入口を表示する。登録要求は既存Rust Brokerへ送り、native Owner確認の同一payload hashへ一回だけ結合する。LinuxではGTK Runnerのprivate helper往復を使用し、FlutterはOwner確認boolやOwner資格を保持しない。Owner拒否はHost登録を成立させず自動再送しない。許可後も登録状態は`pending_review`、公開範囲は`metadata_only`に固定し、remote接続、Trust、Permission、Approval、Credential、Task実行権限を生成しない。登録後の表示は現在のBroker観測が一致しない限り、別Hostのlive状態を未観測として示す。

## 残存範囲

- live Host再接続、Trust検証、Runtime／Agentの個別remote discoveryは`release_blocker`。
- Host間Permission転用拒否とHost切替receiptの監査はC18で検証する。
- C18のHost操作面だけでHostの実接続やD4 Pocket全体のrelease readinessを主張しない。
