## 7. Git 基準・二世代復旧・他者差分

採用作業開始時の local HEAD／`origin/main`／remote `refs/heads/main` は、いずれも `aaebd381815a2eecbbc36bfc28175700dc1105f5` だった。この値は採用前の基準であり、本記録反映後の現在 HEAD を意味しない。採用変更の commit は、本記録を追加した Git 履歴で識別する。

確認した remote 復旧点は次のとおり。

- `refs/tags/codex/backup-main`: `aaebd381815a2eecbbc36bfc28175700dc1105f5`
- `refs/tags/codex/backup-main-prev`: `5bbdcace50a59b8f9d1638cf8e1f5ff6a2835e5c`

二世代は相異し、prev は採用前 main の祖先であることを確認した。採用前 main がすでに backup-main と一致するため、この有効な二世代を再利用し、prev も同じ SHA になる無意味な回転は行わない。以後状態が変われば現在 ref と到達性を再確認する。指定された二 ref の必要な回転と、main／任意 ref の無条件 force push を混同しない。

この作業 clone の開始時 status は clean で、同 clone 内の worktree は main 一つだった。これだけで別 clone・別機器の Writer 不在を証明したとはしない。今回の単一 Writer は他者 dirty／staged／untracked／別 worktree／履歴を保全し、許可された統治更新だけを stage し、通常 commit／push の直前に remote main を再照合する。競合や non-fast-forward は強制せず、対象差分と再開条件を確認する。
