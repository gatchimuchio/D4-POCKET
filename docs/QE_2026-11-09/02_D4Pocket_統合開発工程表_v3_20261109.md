# D4 Pocket 統合開発工程表 v3.0

文書ID：D4-QE-ROADMAP-20261109／作成日：2026-11-09／仕様：D4-QE-SPEC-20261109／施工指示：D4-QE-CODEX-20261109。
対象：D4 Pocket全製品。現状固定点：origin/main 319833cec73d1536310d00071153823e2fd0dbed。状態：改訂成果・未取込。
本書の工程単位＝全体系施工線／全要求接続／全体検収。W00〜W08、P0〜P13、B0〜B6、Q0〜Q7、C0〜C34、Phase0〜45は履歴・要求・検収識別子であり、全製品BUILDの着手順にしない。

## 0. 主語・目的・工程制約

主語［実仕事］＝AI／LLM／Agent。主語［身体］＝D4 Pocket。主語［利用］＝製品使用者。主語［製造］＝施工者Codex。主語［実行権限］＝Rust Broker。主語［設計採否］＝設計者・指示者。主語［正式配布］＝出荷責任者。
目的＝製品使用者の一般目的→AIによる必要Capabilityの自律選択・実行→実結果のAI再消費→継続・完成・停止・回復を、一つの製品・全必須OS・全既存機能で成立させる。

現行の非合理：
- 旧工程表：W00→W01をCLOSED→W02をCLOSED→W03着手→…→W08。実装を受入ゲートの連鎖に従属させる。
- 実際の依存：権限Contract／Broker／Task・Tool・Sessionの接続は全機能の共通インフラ。W02のLIVE_PRODUCT未成立、OS実機不在、B5の原因未解決は、Compose・A2A・Export・独立OSコードの製造自体を妨げない。
- 是正：全製品構造・全機能producer／consumerを最初に設計固定→全N・旧P/B/BUF・全OSを一括BUILD→全系結合→BUILD_COVERED→実物全体QC→OS／機能別QA→正式出荷判断。G1〜G7は受入を管理し、施工線を止める条件にはしない。

安全・重大技術前提だけは例外。権限未確認・認可破綻・不可逆履歴消失・単一writer衝突等はその対象作用を停止し、独立施工は続行する。契約先行の設計と、検収先行の開発凍結を混同しない。

## 1. 新工程：一巡で全機能を施工する

| ステージ | 全体系で行う操作 | 通過条件・してはならないこと |
|---|---|---|
| QE_DESIGN | 既存コード・全N／P／BUF／C／Phase／OS・全consumer・安全責任・相互依存・失敗条件を1つの実装配置へ統合。W00既存全数照合を差分のみ再利用 | 全要求の実装先・契約・生産側と消費側・禁止越境・出力・試験接続を確定。未確認を隠さない。成果物は計画だけで製品PASSを主張しない |
| QE_BUILD［全体施工］ | 施工線A〜Jを**同じBUILD期間に着手**。既存生産コードを再利用し、全Nの目的→実作用→実consumerを同じアーキテクチャで形成 | W02/G2、B5、実機・署名のCLOSEDを他線の着手条件にしない。個別UI、Manifest、Schemaだけを完成としない |
| SYSTEM_SHAPED | Windows最優先の通常入口からAI→Broker→Tool→AI結果消費→Audit／Recoveryという一仕事を実動作させ、他能力へ同じ実行境界を反映 | 1つの局所実仕事が成立。全機能完成や正式installed・出荷の合格ではない |
| BUILD_COVERED | N01〜N11、全歴史的要求、統合機能群K01〜K20、OS別consumerの**全数**に対してproduction接続・型・否定・回復の存在を確認 | 全必須機能の配線が実コードで存在。BUILD_GAPが必要対象に残れば未達。BLOCKED_AUTHORITYと未実装を区別。Mock代替は禁止 |
| QE_QC | 同一統合候補の実物に対し正例・拒否・故障・長時間・資源・副作用・OS差・回復をまとめて実施。根因に応じて上流を修正 | 該当安全負例はBUILD中にも実施。全体QCを機能ごとの施工の前提にはしない |
| QE_QA | 同一候補／OS／Runtime／機能／証拠範囲を単位として保証可否を判定 | QA_SCOPED／QA_NOT_ESTABLISHED／OUT_OF_SCOPEの区別。実機未取得を合格にしない |
| QE_RELEASE_REVIEW | Strict Release Gate、Blocker、正式証拠・署名・Publisher／Audit鍵・出荷責任者GOを独立判断 | 技術完成だけでrelease_ready=trueを生成しない |

施工の実務上の小単位は、1レイヤーだけではなく**1つの機能作用を全レイヤーで閉じる縦断差分**。BUILD_BATCHは共通Contract変更、影響のあるRust／Flutter／OS／Schema／Testを束ねた実際の意味単位。小単位の都度全suite・正式QC／QA・2世代backup・commitを繰り返さない。重大安全変更の局所負例は即実行。

順序規則＝A〜Jの全てを初期BUILD母集団へ同時割当。安全なContract依存・コンパイル依存は局所順序として許容。**AのG2が閉じるまでB/C/D/E/H/Iのコードに着手しない、という待機は禁止。** Windows実環境は確認可能な機能・品質の優先検証面。Linux／Mac／Mobileの未入手をソース開発の延期理由にしない。

### 2.1 共有Contractを一度で全consumerに適用

| 共有関係 | producer→全consumer | 必須保持条件 |
|---|---|---|
| Task／Capability／Result | Shell Core・Adapter→MCP／A2A／Compare／Handoff／Compose／UI／Export | Runtime差・結果依存・unsupported・session束縛 |
| Identity／Authority | Broker→Task／Tool／Credential／Workspace／Host／OS native／Installer | Permission・Approvalの発生・期限・単回性、secret非投影 |
| Execution／Recovery | Broker worker→MCP stdio／CLI／A2A／Host／process tree／Scratch | Cancel・deadline・crash・接続断・重複送信・Audit finality |
| Configuration／Export | Catalog・Module・Profile→Compose／独立App／Setup／Update | 実能力が構成を消費、Profileで許可を生成しない |
| Evidence／Manifest | Source・Contract・Test→OS別artifact／QA／Release | 現候補同一性、実物とfixtureの分離、旧履歴非遡及 |

実装上の衝突はContract／Producer／Consumer全数のどこで発生したかを特定して**共通の生成原因を修正**。1画面だけのpatchで他画面へ同じ不具合を移すことは禁止。

## 3. 実行中の新規作業投入・BUILD_BATCH制御

| 区分 | 作業開始・継続 | QCとGit |
|---|---|---|
| 全体系設計基線 | 最新指示・AGENTS・全過去採用資料・W00表・現HEAD／source／code／Contractを取り込み、全施工線の実体と差分を確定 | 再調査の全件繰り返しは不要。旧台帳を再使用し新差分を追記 |
| 横断BUILD_BATCH | 各Batchで2つ以上の関連レイヤー／実consumerを実装。全10線の作業を継続的に進める | 必要なlocal compile、Schema／Conformance、正常・拒否・失敗を差分限定で検証。安全criticalは即時 |
| 横断結合チェック | Task→Tool→AI、Runtime差、A2A、Compose／Export、Win／Linux／Mac／Mobile contractを全要求へ接続 | 実機不足をBLOCKED_AUTHORITY／EVIDENCE_MISSING、未実装をBUILD_GAPとして区別 |
| BUILD_COVERED監査 | N01〜N11と全旧P/B/BUF／C／Phase、全OSの実consumerを一巡して照合 | 未接続の必須作用が残れば戻る。新要求の勝手な削除やMVP化禁止 |
| 全体QC／正式Q | 機能が全体として結合した後に同一候補をQ0凍結して実物QC／対象別QA | FAIL→対象・前提・設計まで必要なら遡り是正。旧候補は履歴として保持 |
| 出荷 | Windows trackと他OS・Mobileの個別範囲、18 Blocker、正式署名／責任者決裁を判定 | release_ready=falseを合格前に変えない |

BUILD_BATCH末：実装diff、Rust／Flutter／Schema／Conformance／negative／実consumer、Git二世代backup tag・direct-main・remote HEAD・rollback point、未成立の原因を一組で閉じる。毎行・毎コミットの小分けは禁止ではないが、**毎小単位の全体系検査・独立完了宣言はしない**。既存regressionが発生した場合は構造に応じ原因へ帰還。
